## Next Work

### Test Coverage

Add tests for the Markdown validator, including safe documents, missing headings, and sensitive-data detection.

### Tooling Quality

Add static analysis after the scripts grow enough to justify another dependency. Keep runtime tooling based on the Python standard library where practical.

### Case Study Depth

Add a new case study only when authorized work provides a distinct defensive lesson. Avoid duplicate vulnerability classes added for volume.

### Portfolio Evidence

Add screenshots only after a safe source image exists and passes the review process in `screenshots/README.md`.

### Research Measurement

Track simple repository metrics such as test count, case-study count, and validation status. Do not publish private program statistics or target-specific data.

## Maintenance Rule

Update this roadmap when priorities change. Keep planned work tied to a clear security, engineering, or portfolio benefit.
